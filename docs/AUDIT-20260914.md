# NYXUS SUXYN — Full Build Audit

**Date:** 2026-09-14
**Audited revision:** `fc08af3` (main)
**Host:** eDP-1 1920×1200 + HDMI-A-1, Hyprland, Quickshell 0.3.1
**Theme under test:** MAGMA (ICE verified by source coverage — see §4)

---

## 0. The one-paragraph answer

The build is **good**. It is further along and more internally
disciplined than most desktop shells that ship. The surfaces work, the
theme system is architecturally correct, the runtime is clean, and the
code carries an unusual amount of recorded reasoning that made this audit
possible at all.

The audit found one structural problem that had nothing to do with the
shell's quality: **the build was not reproducible away from this
machine.** Most of the programs the shell calls when you click things
lived only in this laptop's `bin` directories. Ship that ISO and it
installs, boots, looks right — and a large number of buttons do nothing.

**That has been fixed during this audit** (§5). All 198 tools are now
vendored in `repo/bin`, installed by `apply-shell.sh`, staged by
`build-iso.sh`, and protected by two guards that fail the build rather
than ship a broken image.

**Rating: 8.6 / 10** as an artifact. **8 / 10** as a shippable release —
the remaining gap is documentation and a clean-machine bake, not code.
Detail in §8 and §9.

## 3. Defects found and fixed during this audit

All are committed and pushed.

### 3.1 Dock icon reflections were missing — three stacked causes

This had defeated several previous attempts, and the reason is that
there were **three independent faults**, so fixing any one of them
changed nothing visible and looked like a failure.

1. The dock mirrored the **raw theme PNG**, not the lit gem.
   Colourisation preserves luminance, so a dark-maroon source at ~35%
   alpha over the dark seam measured **71/255 against a 66/255
   background**. It was rendering the entire time. It was invisible.
2. The reflection box ran to `y=146` inside a **106 px window whose
   bottom edge is the screen's bottom edge**. Only 14 px could ever
   exist.
3. `ShaderEffectSource.sourceRect` **with a negative `y` yields an empty
   texture.** It fails silently and looks exactly like the bug it was
   added to fix.

Fixed by adding a `mirrorOf` live-capture path to `Reflection.qml`.

> ⚠ **Two traps recorded for whoever touches this next.** The capture
> source must be a **peer** of `srcBox` feeding `MultiEffect.source`
> directly — nested inside `srcBox`'s hidden `layer.enabled` item it
> renders nothing, and so does a bare `ShaderEffect`. And **never
> re-add the negative `sourceRect`**; the squash it bought is under 3 px
> across the visible band, because the mask governs perceived reflection
> length, not the geometry.

### 3.2 Dock gems and sigil sat on different baselines

Gems and the sigil disc now share **one contact line at `y=78`**,
`reflectGap` 8→6, dock reflection `depth: 0.40` so the fall finishes
inside the 22 px available instead of being amputated by the screen edge.

### 3.3 Visualizer jitter — a missing attack ramp

The engine applies a **release** ramp and **no attack ramp at all**; a
rising column is written straight in. That was correct while `SP_DRIFT`
coupled the field. Setting `SP_DRIFT = 0.0` was the right call — columns
should "hit at different times with the sounds" — but it removed the only
thing damping a single-frame spike, leaving 64 columns free to jump
full-scale and back inside two frames.

Fixed with a **display-only attack ramp** (0.55, ≈43 ms rise) in
`BarSpectrum.qml`. Per-column, so independence is untouched. `levels`
stays raw for the note picker.

> ⚠ The fix is **not** more release (that damps the fall, which is the
> liquid part that works) and **not** re-enabling drift (that re-breaks
> "hit at different times").

### 3.4 Icons read yellow — a tonemap failure, not a palette failure

This is why pulling green out of individual terms kept not being enough.

Warm terms **stack** on the crust frame to roughly `(4.3, 1.40, 0.22)` —
a correct 3:1 ember ratio. Then `1 - exp(-col * 1.4)` runs. Red at 4.3
maps to 0.998 and is **pinned**; green at 1.40 maps to 0.859 and is still
climbing. A ratio that went in at 3:1 comes out at **1.1:1, which is
yellow.** The tonemap did not tint anything — it ran red out of headroom
and let green catch up.

Fixed with a hot-hue guard applied *after* the stack and *before* the
curve, acting only above 1.0 so every mid-tone keeps its authored warmth.

**Measured hot-pixel G/R: 0.73 → 0.55.** (Yellow ≈ 0.9–1.0, orange ≈ 0.5.)

Also added a **pale-glacier catch-light** gated on sky-facing normals.
A tile lit by one colour family has no cool reference anywhere on it, so
every edge is warm-on-warm and the form cannot be read at 54 px. It is a
*light*, not a hue shift — the face and all downward facets stay ember.

### 3.5 The widget on/off switch never subscribed to its own key

`widgetOn()` used a bracket lookup, `adapter["widget_" + slug]` — sitting
**two lines above the comment explaining why bracket lookups are wrong.**
The fix had been applied to `widgetX`, `widgetY` and `widgetPlaced`; the
on/off switch itself was left behind.

Bracket access on a `JsonAdapter` creates no binding subscription, and
`Widgets.qml` binds visibility through this function. Toggling a widget
in Settings wrote the key and the binding never re-evaluated. **It read
as a dead switch.** It also appeared to work intermittently, because any
other change in the same binding dragged a re-evaluation along with it.

### 3.6 Calamares called three binaries the ISO never shipped

`nyxus-fde-wire`, `nyxus-fde-check` and `nyxus-hibernate` are named
directly by Calamares module configs but were never staged into the
profile and never copied by `build-iso.sh`. They worked only because they
existed in `/usr/local/bin` **on the one machine that had ever baked**.

Baked anywhere else the ISO still builds and still installs —
**full-disk encryption wiring and hibernate setup simply do not happen.**
The FDE shellprocess ends in `|| true`, so there is not even an installer
error to notice.

Staged, and a **guard** added: every `/usr/local/{bin,sbin}/nyxus-*` path
mentioned anywhere under `iso-builder/` must resolve to a staged file, or
the bake dies.

### 3.7 Settings entries that did nothing

Per the standing rule that every Settings entry works or goes:

- `app_media_resume` — **was dead.** Now wired and proven live (resume
  verified at 122 s into a track).
- `app_media_repeat` — **was dead.** Now wired and proven live against
  VLC, which unlike Chromium publishes `LoopStatus`.

> ⚠ `_pushRepeat` must read `src.player` **directly**. Reading the
> derived `loopSupported` from `onPlayerChanged` returns the *outgoing*
> player's value — a binding-evaluation-order trap, the same class as the
> earlier `Station`/`BarSeam` loops.

Investigated and cleared as **false positives** (they are wired, via
accessors a naive grep misses): `font_hinting`, `font_rgba`,
`print_paper`, `print_duplex`, `print_quality`, `app_media_auto_mixes`,
`lock_moon_scale`, all `ui_sound_*`, all `tape_*`, all `widget_*`.

### 3.8 Other fixes landed

- **The Brain panel could not open at all** — `Bus.qml` was missing
  `brainOpen`.
- Two **binding loops** (`BarSeam`, `Station`).
- Two **`qmldir` defects**: a dangling `TapeLamp` entry that warned on
  every clean clone, and `MagmaSlab` — which shipped with a built shader
  and documentation but **was never a resolvable type**.
- **Hardcoded `/home/gowski`** scrubbed from `Floor3D.qml` and
  `FloorPageMovies.qml`.
- A **272 MB stray nested clone** and `__pycache__` deleted.

## 4. Theme system — verdict: **architecturally sound**

This was the top concern ("not everything switches over"). It checks out.

| Check | Result |
|---|---|
| Colour tokens in `Theme.qml` | 105 |
| Explicitly `lookMagma ? … : …` mapped | 41 |
| Unmapped tokens carrying literal hex | 12 |
| Of those, *palette primitives* (`iceTeal`, `icePlum`, `magmaEmber`, `magmaGold`) | correct — they **feed** the mapped tokens |
| Of those, *semantic non-theme* (`text`, `ok`, `danger`, `accentInk`) | correct — status colours must not drift with theme |
| `Theme.icePlum` used directly by any widget | **0 files** |
| `Theme.iceTeal` used directly by any widget | **0 files** |

The plum tokens users were seeing bleed through (`plumHaze`, `plumDeep`)
**are** theme-mapped and do switch.

The only direct consumers of ice primitives are `FloorHub`,
`FloorDoor`, `FloorPage{Movies,Music,Games}` — and `Theme.qml` documents
this as intentional: *"Floor hub wears BOTH layers at once (ice/plum +
magma). Never remapped."*

Likewise the neon `#ff2bd6` / `#00e5ff` / `#ffea00` triad appears only in
`Floor*` / `Arcade*` files. That is a **deliberate separate design
language**, not theme leakage.

**Conclusion:** the theme switch is complete. There is no orphaned
surface. The toggle in Settings → Appearance writes five coordinated keys
(`look_set`, `swirl_preview`, `swirl_mode`, `sky_mode`,
`layered_wall_base`) so the wallpaper cannot desynchronise from the
palette.

> **Note on persistence, tested directly:** an external edit to
> `settings.json` was **correctly rejected** — the store's in-memory
> model flushed over it and self-healed back to the real value. Settings
> survive because the store owns the file. That is the right behaviour
> and it means theme choice survives logout and reboot.

## 5. ✅ The release blocker — found and closed

**19 of the 20 programs the shell actually spawns were neither in this
repository nor staged in the ISO.**

| | |
|---|---|
| Distinct `nyxus-*` tools on this machine | **243** |
| Combined size | 7.7 MB |
| Tools the shell spawns | 20 |
| Of those, present in the repo | **1** (`nyxus-hwcaps`) |
| Combined size of the 20 | 452 KB |

The missing set includes `nyxus-brightness`, `nyxus-files`,
`nyxus-media`, `nyxus-sound`, `nyxus-backup`, `nyxus-lyrics`,
`nyxus-tape`, `nyxus-doctor`, `nyxus-update`, `nyxus-status`,
`nyxus-secure`, `nyxus-house`, `nyxus-hemera`, and **`nyxus-beat-engine`
— the program that drives the music visualizer.**

`build-iso.sh` copies binaries **from the baking machine's**
`/usr/local/bin`, and only three by name. Everything else is inherited
from this laptop's accumulated state.

**What this means concretely:** on a fresh install, the shell starts, the
theme is correct, the bar renders — and brightness does nothing, the file
manager does not open, the visualizer never moves, backup does nothing,
and the updater does not run.

On *this* machine every one of those 20 resolves, which is exactly why
the problem is invisible from inside the build.

### What was done about it

| Step | Result |
|---|---|
| Vendored every `nyxus-*` tool into `repo/bin` | **198 files, 7.6 MB** |
| Deduplicated the two source dirs | 4 tools differed; took the copy that actually runs (PATH order) |
| Secret scan | **0 credentials.** Only variable assignments reading config/user input |
| Personal-path scan | **16 occurrences of `/home/gowski` across 8 files — all scrubbed** |
| Syntax check, all 198 | **0 failures** (bash + python) |
| `apply-shell.sh` | now installs `bin/` → `~/.local/bin`, and warns if that is not on `PATH` |
| `build-iso.sh` | now stages `repo/bin` wholesale instead of copying from the baker |
| Guard: referenced binaries | every `/usr/local/{bin,sbin}/nyxus-*` path named under `iso-builder/` must be staged |
| Guard: spawned commands | every `nyxus-*` the QML launches must be in the image |

The personal-path scrub reused the idiom already established in
`tools/nyxus-repair-at-root`:

```sh
OWNER_HOME=$(getent passwd "${SUDO_USER:-$USER}" | cut -d: -f6)
OWNER_HOME=${OWNER_HOME:-$HOME}
```

Verified equivalent on this machine (resolves to `/home/gowski`), so the
scrubbed scripts behave identically here and correctly everywhere else.

> ⚠ **The spawned-command guard has two spawn styles to cover, and the
> first version only covered one.** It scanned `command: [...]` arrays,
> passed cleanly, and was then caught by a negative test: deleting
> `nyxus-beat-engine` from a simulated stage did **not** trip it, because
> the visualizer's engine is launched from inside a shell string
> (`… exec nyxus-beat-engine --tap "$1"`). A guard with a blind spot over
> the exact binary that started this audit is worse than no guard,
> because it reads as proof. Both guards are now verified in **both**
> directions — they pass on a full stage and fail on a missing tool.

## 9. What would make it perfect

**In priority order. The first item is worth more than all the rest.**

1. ~~**Vendor the tooling.**~~ ✅ **Done during this audit.** 198 tools in
   `repo/bin`, installed by `apply-shell.sh`, staged by `build-iso.sh`,
   two guards verified in both directions. *This converts the project
   from "works on one laptop" to "works for anyone."*

2. **Bake on a clean machine and prove it.** ← **now the top item.** A VM install, then walk the
   surfaces. Every remaining host-state dependency will surface in one
   pass. Nothing else substitutes for this.

3. **Shrink the history.** 134 MB of `.git` for 9 MB of source. Large
   binaries in history — consider `git-filter-repo` or an orphan-root
   release branch.

4. **Write the architecture doc.** One file: how `Theme` → `Prefs` →
   `SettingsStore` fit together, the layer-shell model, and where the
   traps are. The traps are already documented at their sites; they just
   need an index.

5. **Add a smoke test.** A script that starts the shell headless, waits
   for `Configuration Loaded`, and fails on any `WARN`/`error`. The
   runtime is already clean — lock it in so it stays that way.

6. **Clean the environment.** 43 `.bak` in the live config, three `.bak`
   variants of `nyxus-radial-greeter` sitting on the system `PATH`.

7. **Demote the beat log line** to debug.

### Features worth considering (none required)

- **A theme preview** in Settings → Appearance. The tokens exist; a small
  swatch strip would let the user see ICE before committing.
- **A third theme slot.** The architecture already supports it — the
  switch is one string. Proving a third look would validate that the
  abstraction is real rather than a two-case special case.
- **Per-monitor theme.** Dual-head is already handled everywhere; this
  would be a genuinely unusual capability.
- **`nyxus-doctor` as a first-class panel.** The tool exists; surfacing
  it in Settings would make the system self-diagnosing — which matters a
  lot for a build that "all will use."

## 10. Bottom line

The craft here is real, and it is visible in the parts that are hard:
the reflection recipe, the tonemap analysis, the contact line, the
binding-subscription discipline, 90,000 lines without a single abandoned
TODO. The audit found bugs, but it found them **because the code
explains itself well enough to be checked** — that is not the normal
case, and it is the strongest signal in this report.

The structural gap that stood between "beautiful thing that runs here"
and "system anyone can install" is closed. The tooling is vendored, the
installer deploys it, the ISO stages it, and two guards make sure it
stays that way.

What remains is a bake on a clean machine to prove it end to end, and a
document that orients a newcomer. Neither is a code problem.

**This is ready to test as a release candidate.**
